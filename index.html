v4 TypeORM, ready for deployment

Create, migrate, check.

TypeORM maps your entities and runs your migrations. typeorm-extension covers the rest of a deployment: the database has to exist, replicas start at once, the schema can drift from the entities, and every driver reports a duplicate key differently.

The parts TypeORM leaves to you.

Each one works on its own; use the ones your deployment needs.

  • 01

    Create and drop

    createDatabase() speaks each dialect, skips an existing database and then runs the migrations or synchronize().

    await createDatabase({ options })
  • 02

    Schema drift

    Fails the deploy when the migrations and the entities describe different schemas, and lists the statements that would reconcile them.

    npx typeorm-extension db drift
  • 03

    Repair migrations

    renameIndex, renameForeignKey and changeColumnType read the current state first and return false when already applied.

    renameIndex(queryRunner, { table, from, to })
  • 04

    Locks

    A named advisory lock for one replica at a time, and a row read with a write lock inside a transaction.

    withDatabaseLock(queryRunner, 'migrations', fn)
  • 05

    Error classification

    Recognize a unique or foreign key violation and a lock conflict, whichever driver raised it.

    if (isDatabaseUniqueViolationError(e)) { … }
  • 06

    Seeding

    Seeder classes and factories, run by seed run, optionally tracked so each seeder runs once.

    await factoryManager.get(User).saveMany(5)

What you stop writing.

The same deployment concerns, without and with typeorm-extension.

ConcernWithout itWith it
The database existsConnect to a server-level database and run each dialect's own CREATE DATABASE.createDatabase() or db create. Skips an existing database.
Several replicas migrateEach replica runs the migrations at boot, or you hand-roll pg_advisory_lock / GET_LOCK.withDatabaseLock(): one session at a time, released also when the callback throws.
Migrations drift from the entitiesNoticed when the next generated migration contains unrelated changes.assertSchemaMatchesMetadata() or db drift fails the deploy.
Read-modify-write racesTwo requests read the same row, both pass the check, both write.withLockedEntity() reads the row with a write lock inside a transaction.
A failed writeRead code, number or errorNum, depending on the driver.isDatabaseUniqueViolationError(e) knows where each driver puts the code.
Development and test dataAd-hoc scripts that insert rows and break on the second run.Seeders and factories, tracked so each seeder runs once.

From data source to seeded database

Describe the data source once. The CLI finds data-source.ts in src/ and creates, checks and seeds from it.

Installation →
import { DataSource, DataSourceOptions } from 'typeorm';import { SeederOptions } from 'typeorm-extension'; export const options: DataSourceOptions & SeederOptions = {    type: 'postgres',    database: 'app',    seeds: ['src/database/seeds/**/*{.ts,.js}'],    factories: ['src/database/factories/**/*{.ts,.js}'],}; export const dataSource = new DataSource(options);
